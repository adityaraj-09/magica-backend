---
title: Messages and completions
description: Submit a durable agent turn. The HTTP call returns as soon as the run is queued.
---

You do **not** have to create a chat first. `POST /api/v1/completions` without `chatId` creates a chat and queues the turn. `POST /api/v1/chats` then `POST /api/v1/chats/{chatId}/messages` is still supported when you want an empty chat or a title first.

All send routes admit one turn. They share the same body fields. A repeat `clientMessageId` replays the original admission and does not start a second run.

## Request

<ParamField body="text" type="string">
  Turn text, up to 8192 characters. Required unless `prompt` or `messages` supplies it.
</ParamField>
<ParamField body="prompt" type="string">
  Alias of `text` on completion routes.
</ParamField>
<ParamField body="messages" type="object[]">
  OpenAI-style `{ role, content }`. The last `user` message is the turn text.
</ParamField>
<ParamField body="clientMessageId" type="string">
  UUID. Same id returns the original `200` replay.
</ParamField>
<ParamField body="planMode" type="boolean">
  When true, the agent pauses for plan approval before tools.
</ParamField>
<ParamField body="image_urls" type="string[]">
  Public `http(s)` image URLs to attach. The agent sees them as images. You do not upload to Transloadit first. At most 8 files when combined with `attachmentIds`.
</ParamField>
<ParamField body="image_url" type="string">
  Single public image URL. Same as one item in `image_urls`.
</ParamField>
<ParamField body="attachmentIds" type="string[]">
  IDs of files you already uploaded in the product. Same-chat files are direct uploads; others come from the library.
</ParamField>
<ParamField body="chatId" type="string">
  Only on `POST /api/v1/completions`. **Omit it to send a first message** (a chat is created). Pass it to continue an existing chat.
</ParamField>

```json
{
  "text": "What is in this photo?",
  "image_urls": ["https://cdn.example.com/photo.jpg"],
  "clientMessageId": "11111111-1111-4111-8111-111111111111",
  "planMode": false
}
```

## Response

`POST /chats/{chatId}/messages` returns `201`, or `200` when `clientMessageId` is replayed. `POST /chats/{chatId}/completions` returns `202`, or `200` on replay. `POST /completions` returns `202`.

<ResponseField name="chatId" type="string" />
<ResponseField name="messageId" type="string" />
<ResponseField name="runId" type="string">
  Poll this on the runs route.
</ResponseField>
<ResponseField name="triggerRunId" type="string">
  Orchestrator id. Nullable if dispatch has not attached yet.
</ResponseField>
<ResponseField name="status" type="string">
  Always `queued` at admission. Later states are on the run snapshot.
</ResponseField>

## Routes

| Method | Path | When |
| --- | --- | --- |
| POST | `/api/v1/completions` | **Preferred.** Omit `chatId` to start a chat, or pass it to continue |
| POST | `/api/v1/chats/{chatId}/messages` | Existing chat only |
| POST | `/api/v1/chats/{chatId}/completions` | Same admission, chat-style body |

`GET /api/v1/chats/{chatId}/messages` lists history, newest first, with `limit` and `cursor`. Each message includes `contentBlocks` and `attachments`.

<Note>
  One active run per chat. A second send before the run reaches `COMPLETE`, `FAILED`, or `CANCELLED` returns `409 RUN_ACTIVE`.
</Note>
